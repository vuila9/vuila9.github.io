    Online save file editor

    A free save editor that runs entirely in your browser. Drop in a game save (.bin, .sav, .dat or .json) and it works out how the file is packed: MessagePack binary JSON, compressed with GZip or zlib, Base64 or hex encoded, XOR scrambled, or JSON inside a binary wrapper. It then shows every value, like gold, gems, levels, items and unlocks, as a searchable list you can edit in place. When you're done, it packs the file back the same way and you download a drop-in replacement. You can also convert the save to JSON.

    How to edit a save file

    1. Back up the original save file and keep the copy somewhere safe.
    2. Drop the file onto the box above, or click it to browse. The detected format (for example MessagePack or GZip → JSON) is shown at the top.
    3. Find the value with the search box, or use Show to list only numbers, booleans or strings.
    4. Edit it right in the list. Use the JSON tab to add or remove fields.
    5. Download file and replace the original save with it. Use Export JSON for a readable copy.
    FAQ

    How do I open and edit a .bin save file?

    Drop the .bin file onto the box at the top of this page. It detects how the save is packed (MessagePack, JSON, GZip, Base64, XOR…) and lists every value with its path. Change the numbers, text or true/false values you want, then press Download file to get the edited save.

    Can I convert a .bin save file to JSON?

    Yes. Once the save is opened, press Export JSON to download a readable .json copy, or use the JSON tab to view and edit the whole file as JSON.

    Is my save file uploaded anywhere?

    No. The editor runs entirely in your browser with JavaScript. The file is read, decoded and rebuilt on your own device and never sent to a server.

    Which save formats are supported?

    MessagePack (binary JSON, common in Unity and C# games), plain JSON in UTF-8 or UTF-16, and saves wrapped in GZip, zlib or Deflate compression, Base64 or hex text, single-byte XOR, or a binary header. Any other file can be edited byte by byte in the hex view.

    Why doesn't my game load the edited save?

    Some games protect their saves with real encryption or a checksum, so any change makes the game reject the file. Those saves can be viewed in the hex view but not edited safely. Always keep a backup of the original save.

    Features
    • Format detection: peels off GZip, zlib, raw Deflate, Base64 (incl. URL-safe), hex text and single-byte XOR layers in any order, then reads UTF-8 / UTF-16 text with or without a BOM.
    • MessagePack: binary "JSON" saves (common in Unity / C# games) are decoded into readable values and rebuilt on download, keeping each number's exact binary type (int8…int64, float32/float64).
    • Quick edit: every number, string and true/false value as a flat list with its full path, filterable by type, searchable, and paginated for big saves.
    • JSON mode: the whole document as text, for adding or removing fields, array items or whole sections.
    • Lossless round-trip: a custom JSON parser keeps numbers exactly as written (9931676.0 stays a float, 64-bit IDs keep every digit), along with key order, duplicate keys, escapes and the original indentation.
    • Binary wrappers: JSON stored between a binary header and footer is found automatically, and a length field in front of it (uint16/uint32 or C#'s 7-bit varint) is updated when the JSON grows or shrinks.
    • Hex view: files with an unknown format can still be edited byte by byte.
    Limitations
    • Saves protected by real encryption (AES, etc.) or a checksum/signature can be viewed in hex but won't load in the game after editing.
    • Other binary serializers (Unity BinaryFormatter, Protobuf…) aren't decoded into fields yet; use the hex view.
    • Compressed layers are re-compressed by the browser, so the bytes differ from the original even when the content is identical. Games read it the same.
    • Always keep a backup of the original save.
